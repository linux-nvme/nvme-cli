nvme-check-tls-key(1)
=====================

NAME
----
nvme-check-tls-key - Check a NVMe TLS PSK (deprecated)

SYNOPSIS
--------
[verse]
'nvme' [<global-options>] 'check-tls-key' [--keyring=<name> | -k <name>]
			[--keytype=<type> | -t <type>]
			[--hostnqn=<nqn> | -n <nqn>]
			[--subsysnqn=<nqn> | -c <nqn>]
			[--keydata=<key> | -d <key>]
			[--identity=<id-vers> | -I <id-vers>]
			[--compat | -C]

DESCRIPTION
-----------
Deprecated alias for linknvme-keys-check-tls[1], kept for scripts written
against nvme-cli versions older than 3.0.

One difference: the old 'check-tls-key' also accepted '--insert'/'-i' to
derive and store a TLS PSK directly, but the new 'check-tls' never
modifies the keyring -- that functionality moved to
linknvme-keys-insert-tls[1]. Scripts relying on '--insert' here will get an
"unrecognized option" error and must switch to 'nvme keys insert-tls'
directly; all other options continue to work unchanged through this alias.

New scripts should use 'nvme keys check-tls' instead. This alias prints a
deprecation warning on stderr and may be removed in a future release.

See linknvme-keys-check-tls[1] for the full option reference.
